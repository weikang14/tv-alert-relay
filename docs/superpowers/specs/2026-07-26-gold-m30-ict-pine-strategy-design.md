# 黄金 M30 趋势追随 + ICT/SMC 入场 Pine Script 策略 — 设计

日期:2026-07-26
状态:待用户确认

## 背景

用户想验证一个新的黄金（XAUUSD）交易策略思路，先在 TradingView 用 Pine Script
实现成 `strategy()` 脚本，用 TradingView 自带 Strategy Tester 跑出胜率/盈亏比/
最大回撤等数据；如果数据不错，再考虑移植成 MetaTrader EA 接真实券商下单——那是
后续独立项目，本设计不覆盖。

策略与 `TradingBot/goldbot` 现有的 ICT 结构信号引擎（`engine/chartsignal.py`：
unicorn / silver_bullet / po3）无直接代码复用关系，是全新实现，但复用了同一套
ICT/SMC 概念词汇（流动性扫荡、订单块、FVG）。

品种/周期:XAUUSD，M30 入场，H4 方向过滤。

## 一、方向判断（H4）

- H4 EMA50:收盘价在 EMA50 上方 → 多头方向；下方 → 空头方向
- H4 BOS/CHoCH:识别 H4 摆动高低点序列，价格突破前高 → 多头结构；跌破前低 →
  空头结构
- 两者任一支持即可（OR）:EMA50 方向或 BOS/CHoCH 方向有一个成立，对应方向就
  视为"允许交易的方向"

## 二、入场前置条件（M30 回调区域）

- M30 EMA20 > EMA50 视为多头排列区间，EMA20 < EMA50 视为空头排列区间
- 价格回调至 EMA20 附近（容差 0.3×ATR(14)）才进入"入场评分区域"——不在此区域
  不评分、不入场

## 三、ICT/SMC 三因子评分（各 0-100 分）

同一根 K 线上，对当前允许的方向（由第一节方向判断决定）分别计算以下三项：

1. **流动性扫荡**
   - 找最近 10 根 K 线的摆动高/低点（pivot high/low)
   - 触发:当前 K 线影线刺穿该摆动点，但收盘价收回摆动点内侧
   - 评分 = `clamp(0, 100, 刺穿深度 / ATR(14) × 200)`（刺穿达 0.5×ATR 封顶 100）

2. **订单块回踩**
   - 回看窗口 20 根 K 线，找最近一次冲量（连续几根合计涨跌幅 ≥ 2×ATR(14)）前的
     最后一根反向 K 线，标记其高低区间为订单块
   - 触发:当前价格回踩进入该订单块区间
   - 评分 = `clamp(0, 100, 冲量幅度 / ATR(14) × 25)`，按形成后经过的 K 线数衰减
     （每 5 根衰减 10%，超过 50 根视为失效、不参与评分）

3. **公允价值缺口（FVG）回补**
   - 3 根 K 线形态:K1 高点 < K3 低点（看涨缺口，看跌对称:K1 低点 > K3 高点）
   - 触发:当前价格回补进入该缺口区间且缺口尚未被完全回补
   - 评分 = `clamp(0, 100, 缺口大小 / ATR(14) × 150)`

**入场判定：**
- 三项评分中最高分 ≥ 80 → 直接入场（单一高质量信号）
- 否则三项评分之和 ≥ 120 → 共振入场
- 否则不入场

所有系数（刺穿深度倍数、冲量阈值、衰减率、缺口倍数、80/120 两个阈值）都做成
`input.*`，不写死，方便后续调参。

## 四、止盈止损

- SL = 入场价 ± 1.5×ATR(14)
- TP = 入场价 ± 3×ATR(14)（盈亏比 1:2）
- ATR 周期、SL/TP 倍数做成可调输入

## 五、仓位管理

- 按账户权益固定比例风险（默认 1%），用止损距离反推手数
- 同一时间只持一笔仓位，不加仓（不做 pyramiding）

## 六、反向信号处理

- 新信号方向与当前持仓相反时:先平仓再反手（Pine `strategy.entry()` 默认行为，
  无需额外平仓判断代码）

## 七、交易时段

- 不做时段过滤，24 小时评估信号（后续如发现亚盘信号质量差，再加开关，不在本次
  实现范围内）

## 八、日内熔断（风控层）

- 每根 K 线检查当前 bar 的日期，与上一根不同即视为新交易日，记录当日起始权益
  `strategy.equity`
- 触发条件（任一命中即停手，当日不再开新仓，已持仓不受影响、按原 SL/TP 正常
  走完）：
  - 当日浮亏 ≥ 起始权益 × 3%（`input`，默认 3%）
  - 当日连续亏损笔数 ≥ 3（`input`，默认 3）
- 次日（新 bar 日期）自动重置，不需要手动干预
- 熔断状态在图表上用背景色/标签提示，方便回测时识别哪些交易日被跳过

## 九、回测参数

- 手续费:0.03%（`commission_value`，贴近 CFD/ECN 实盘成本）
- 滑点:3 tick（`slippage`）
- 避免默认零成本回测导致数据虚高

## 十、输入参数（`input.*`，全部可调）

- EMA 快/慢周期（默认 20 / 50）
- H4 方向判断的 EMA 周期（默认 50）、BOS/CHoCH 摆动点回看根数（默认 5 根）
- ATR 周期（默认 14）
- SL/TP 的 ATR 倍数（默认 1.5 / 3）
- 回调容差系数（默认 0.3×ATR）
- 流动性扫荡摆动点回看根数（默认 10）
- 订单块回看窗口（默认 20）、冲量阈值倍数（默认 2×ATR）、衰减参数（每 5 根
  衰减 10%、50 根失效）
- 单一信号阈值（默认 80）、共振信号阈值（默认 120）
- 单笔风险比例（默认 1%）
- 单日最大亏损比例（默认 3%）、单日最大连续亏损笔数（默认 3）
- 手续费、滑点

## 十一、图表可视化

- 绘制 M30 EMA20/EMA50 线
- H4 方向用背景色标注（多头/空头/中性）
- 入场箭头 + 触发因子标签（比如标注是"扫荡"/"订单块"/"FVG"/"共振"触发）
- 三项评分可选调试面板（`table.new`），显示当前 K 线三项实时分数，便于人工核对
- 熔断触发日用背景色标注

## 十二、测试/验证计划

1. `pine_set_source` 把脚本注入 TradingView Pine 编辑器
2. `pine_smart_compile` + `pine_get_errors` 确认编译通过、无报错
3. 打开 Strategy Tester，读回测报告（胜率、盈亏比、最大回撤、净利润、交易笔数）
4. 抽样对照几笔历史交易，人工在图上核对评分因子触发是否符合预期（用调试面板）
5. 抽样核对熔断触发日当天确实没有新开仓
6. `pine_save` 存到 TradingView 云端账号，命名区分版本

## 明确不做（YAGNI）

- RSI 等额外过滤因子——先看纯 ICT+EMA 版本效果，不够再加
- 完整多周期入场搜索——只用 H4 做方向过滤，不在小周期上做二次结构搜索
- 交易时段过滤——先跑全时段数据，看是否需要
- 加仓/金字塔（pyramiding）——单笔仓位验证阶段用不到
- 新闻规避（FOMC/NFP/CPI 等事件停手）——Pine Script 没有官方经济日历接口
  （`request.economic()` 只提供已发布的历史指标数值，不含未来事件时间表），
  只能靠手动维护日期表实现，维护成本不为零。本阶段不做，先看回测里高波动
  时段的信号质量再决定。**未来方向**：等做 MetaTrader EA 时，考虑做一个独立
  的后台管理脚本/服务，把新闻规避 + AI 分析都做成外挂在核心交易逻辑之外的
  一层（MetaTrader/MQL 有外部 DLL、WebRequest 等能力，能接经济日历 API 和
  AI 判断，Pine Script 做不到）
- MetaTrader EA 移植——独立后续项目，等这版数据验证完再启动
- 与 goldbot 现有系统（Telegram 推送、Supabase 存储、AI 分析）的任何集成——
  这是一个独立的 TradingView 验证脚本，不接入现有基础设施
